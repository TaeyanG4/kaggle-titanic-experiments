# 01. 실험 설계: 무엇을 확인하려 했나

[프로젝트 홈](../README.md) · [다음: 실험 여정](02-experiment-journey.md)

**프로젝트명:** Kaggle Titanic Experiments (`kaggle-titanic-experiments`)

**대회:** Titanic — Machine Learning from Disaster

## 1. 출발 질문

핵심 질문은 “GPT가 Titanic에서 몇 점을 내는가?”보다 넓습니다.

> 사용자가 설정한 스킬과 자연어 지시를 기반으로, GPT 웹 세션이 가설 수립 → 코드 작성 → 로컬 실행 → 검증 → 실패 분석 → 제출 → 기록까지 얼마나 일관되게 이어갈 수 있는가?

Titanic은 작은 표형 데이터라 많은 후보를 비교할 수 있고, 가족·티켓처럼 관계를 이용하는 피처와 누출 위험을 함께 다룰 수 있었습니다. 이 특징 때문에 단순 모델 학습보다 **실험 운영**을 관찰하는 소재로 사용했습니다. 본 사례의 데이터는 학습 891행과 제출 대상 418행으로 구성되어 있습니다. 원본 파일은 공개 저장소에 재배포하지 않으며 [파일 지문](evidence/data-fingerprints.json)만 남겼습니다.

## 2. 의도한 제약

사용자는 치팅이나 데이터 누출 없이, 직접 구성한 스킬·프롬프트와 GPT 웹 세션만으로 반자동 개선의 한계를 보고자 했습니다. 여기서 “GPT만”은 Python·라이브러리·파일 도구 없이 말로만 예측했다는 뜻이 아닙니다. **코드 작성과 작업 지시의 대화 인터페이스가 GPT 웹 세션이었다**는 운영 설명입니다. 실제 계산은 로컬 Python에서 실행됐습니다.

소유자 설명 기준 초기 세팅은 Antigravity가 담당했습니다. 이후 실행 지시는 GPT 웹 세션을 거쳤고, 사용자는 중간마다 성능·검증·앙상블 구성·다음 계획을 질문했습니다. 제출은 사용자의 승인을 받아 수행했습니다.

이 의도와 달리 역사적 재현 분기에는 엄격한 평가 경계에 맞지 않는 구현이 포함되었습니다. 공개 노트북의 예측 출력도 일부 재사용했습니다. 따라서 의도한 제약을 모든 분기에서 완전히 충족했다고 쓰지 않으며, [03번 보고서](03-validation-and-integrity.md)에 예외를 명시합니다.

## 3. 자동화의 경계

| 작업 | GPT·도구의 역할 | 사람의 역할 |
|---|---|---|
| 초기 방향 | 선택지와 위험 설명 | 프로젝트 목적과 사용 범위 정의 |
| 스킬 활용 | 작업 규약을 읽고 실행 흐름에 적용 | 스킬 설정과 사용 여부 결정 |
| 가설·피처 | 코드와 비교 실험 제안 | 의미·정당성·우선순위 질문 |
| 실행 | 로컬 도구로 파일과 Python 작업 수행 | 실행을 요청하고 중단·재개 지시 |
| 제출 | CSV 검사, 제출 명령, 결과 기록 | 외부 제출 승인 |
| 종료 | 증거·한계·재현 문서 정리 | 종료 및 GitHub 공개 정리 요청 |

수동 개입이 있었으므로 완전 자율성을 주장하지 않습니다. 반대로 사용자가 모든 피처나 모델 파라미터를 직접 작성했다고도 주장하지 않습니다. 관찰 가능한 사실은 **사람이 방향을 정하고 GPT가 상당한 실행 작업을 수행하는 협업 흐름**입니다.

## 4. 무엇을 측정했나

모델별 Accuracy, 일부 ROC-AUC, fold·seed별 변동, 기존 후보와의 불일치, rescue/harm, 제출 점수, 예측 파일 해시를 기록했습니다. 이후 고정 fold 이외에 repeated split, 관계 그룹 분리, X 분포를 맞춘 pseudo-test, train/test 구분 모델, nested selection도 추가했습니다.

Accuracy는 맞힌 예측의 비율입니다. ROC-AUC는 순위 품질을 요약하므로 Accuracy와 동시에 올라야 하는 값이 아닙니다. 실제로 여러 분기에서 AUC 상승과 Accuracy 하락이 함께 관찰됐습니다. 따라서 최종 제출 지표와 보조 진단 지표를 별도 열에 유지했습니다.

OOF는 각 학습 행을 그 행의 타깃으로 학습하지 않은 fold 모델로 예측한 결과를 뜻합니다. 다만 이름에 OOF가 붙어도 **전처리·그룹 통계·모델 선택까지 동일한 경계를 지켰는지**는 별도로 확인해야 합니다. 이 점이 이번 기록의 중요한 감사 항목입니다.

## 5. 측정하지 못한 것

스킬을 사용하지 않은 대조군, 동일 예산의 수동 데이터 과학자 대조군, 프롬프트만 바꾼 무작위 비교, 최초부터 봉인된 최종 평가 데이터는 없습니다. 계산 시간·사용자 노동 시간·모델 사용 비용도 완전한 형태로 수집하지 않았습니다. 따라서 다음 주장은 하지 않습니다.

- “점수 상승은 전적으로 스킬 때문이다.”
- “사람보다 빠르거나 우수하다.”
- “동일 프롬프트면 다른 세션에서도 동일한 결과가 나온다.”
- “83.014%는 새로운 Titanic 유사 데이터에 대한 보장 성능이다.”

대신 **관찰된 작업 흐름과 산출물**을 재검토할 수 있도록 공개합니다. [환경 스냅샷](evidence/environment-snapshot.json)은 종료 시점에 읽은 환경이며, 모든 과거 실행의 패키지 버전을 증명하지 않습니다.

## 6. 시간·버전 범위

이번 보고서의 캠페인은 2026-10-04~05 UTC에 기록된 17개 제출과 그에 연결되는 v1~v47 실험 자료입니다. 날짜는 Kaggle 영수증의 UTC를 기준으로 하며, 한국 시간과 혼용하지 않습니다. 원래 GitHub에 있던 2023년 연습은 [legacy 보관함](../archive/legacy-2023/)에 분리했습니다.

버전 번호는 진행 식별자입니다. 한 버전에 여러 ablation이 있고, 몇몇 버전은 예측 재조립·문서 생성·오류 감사만 수행합니다. 번호 47을 독립 실험 47회, 모델 47개 또는 제출 47회로 해석하면 안 됩니다.

## 7. 종료의 의미

이 저장소의 종료는 “존재하는 모든 Titanic 방법을 소진했다”는 수학적 주장이 아닙니다. 이 캠페인의 비용·증거 수준에서 더 많은 변형을 반복하기보다 **결과를 동결하고 한계를 기록하기로 한 운영 결정**입니다. 새로운 데이터나 검증 계약이 생기면 별도의 사전 등록된 후속 실험을 설계할 수 있습니다.
