# 01. 실험 설계

[프로젝트 홈](../README.md) / [단계별 기록](02-experiment-journey.md)

## 시작한 이유

직접 설정한 스킬과 프롬프트를 활용해 GPT 웹 세션으로 머신러닝 실험을 어디까지 이어갈 수 있는지 보고 싶었다. 한 번 코드를 생성해서 제출하는 것보다, 결과를 확인하고 가설을 바꾸고 실패 이유를 정리하는 반복 과정에 관심이 있었다.

대상은 Kaggle의 Titanic - Machine Learning from Disaster였다. 학습 데이터 891행과 test 418행을 사용했다. 데이터가 작아 여러 모델을 비교할 수 있고, 가족과 티켓 관계처럼 피처의 효과와 누출 위험을 함께 살펴볼 수 있었다. 원본 데이터는 저장소에 재배포하지 않고 [파일 지문](evidence/data-fingerprints.json)을 남겼다.

## 환경과 역할

초기 환경과 프로젝트 설정은 Antigravity에서 진행했다. 이후 계획, 코드 작성, 실행 지시, 분석과 기록 정리는 GPT 웹 세션으로 진행했다. 로컬 파일 도구와 Python 실행 환경을 연결해 실제 실험을 실행했다.

실험 목표와 스킬, 프롬프트는 직접 설정했다. 결과가 이상하거나 설명이 충분하지 않으면 원인과 다음 계획을 다시 질문했고, 외부 제출 여부도 결정했다. GPT는 그 지시를 받아 코드를 만들고 도구를 호출했다. 따라서 완전 자율 에이전트보다 사람과 GPT가 역할을 나눈 반자동 작업에 가깝다.

| 작업 | 진행 방식 |
|---|---|
| 초기 설정 | Antigravity에서 환경과 프로젝트 준비 |
| 실험 방향 | 대화에서 목표와 제약, 다음 질문 결정 |
| 코드와 실행 | GPT 웹 세션이 코드를 작성하고 로컬 도구 호출 |
| 비교 | OOF, fold 결과, 예측 불일치와 제출 점수 확인 |
| 제출 | 승인 후 CSV 검사와 Kaggle 제출 |
| 기록 | 결과와 판단을 plan, discoveries, handoff 등에 저장 |

구체적인 지시 예시는 [운영 방식](04-workflow-and-prompts.md)에 있다.

## 의도한 제약과 실제 기록

치팅이나 정답 조회, 데이터 누출 없이 개선하는 것을 목표로 했다. 외부 정답을 가져와 점수를 만드는 대신 피처와 모델, 검증 방법을 바꿔보려 했다.

실제 기록을 정리하면서 이 목표와 구분해야 할 부분도 확인했다. 공개 방법 재현 코드 중에는 전체 학습 라벨로 관계 통계를 먼저 만든 분기가 있고, Deotte 계열에는 공개 노트북의 개별 예측을 사용한 파일이 있다. 마지막 후보 선택에는 Public 결과가 반영됐다. 이 때문에 모든 분기와 최고점을 무누출 결과라고 설명하지 않는다. 구현별 차이는 [검증과 한계](03-validation-and-integrity.md)에 남겼다.

## 무엇을 측정했나

주 지표는 Accuracy였다. 일부 실험에는 확률 순위의 품질을 보는 ROC-AUC도 기록했다. 모델마다 같은 fold에서 평가한 결과, 다른 split seed에서의 변동, 기존 후보와 달라진 행, rescue와 harm, 제출 파일 해시를 보존했다.

OOF는 각 학습 행을 검증용으로 남겨 예측한 결과다. 이 값을 믿으려면 모델 학습뿐 아니라 전처리와 타깃 통계도 검증 라벨을 사용하지 않아야 한다. 그래서 그룹 통계의 생성 범위와 모델 선택 절차를 별도 감사 대상으로 두었다.

검증은 고정 5-fold에서 시작해 여러 seed의 반복 CV, 관계 그룹 전체를 분리하는 검증, 실제 test의 입력 통계와 비슷한 pseudo-test, nested selection으로 넓혔다. 각 방식은 다른 조건을 보는 것이며, 모두 같은 독립 test를 반복해서 확보한 것은 아니다.

## 측정하지 못한 것

스킬을 사용하지 않은 대조군이나 같은 예산의 수동 실험은 없다. 계산 시간, 사용자의 작업 시간과 모델 사용 비용도 처음부터 완전하게 수집하지 않았다. 점수 상승을 스킬, 프롬프트, 모델 또는 공개 아이디어의 기여로 나누어 계산할 수 없는 이유다.

전체 프롬프트와 스킬 버전을 처음부터 고정하지도 않았다. [환경 스냅샷](evidence/environment-snapshot.json)은 종료 시점에 확인한 환경이며 모든 과거 실행의 상태를 증명하지 않는다. 동일한 대화를 다시 시작하면 같은 코드와 점수가 나온다고 보장할 수는 없다.

## 기록 범위와 종료

이번 기록은 2026년 10월 4~5일 UTC의 17개 제출과 관련 실험을 다룬다. 이전 연습은 [별도 보관함](../archive/legacy-2023/)에 있다. v1부터 v47까지는 작업 식별자이며, 각 버전이 같은 크기의 독립 실험은 아니다.

종료는 가능한 모든 Titanic 기법을 다 시도했다는 뜻이 아니다. 이 작업에서 얻은 코드, 예측, 지표를 보존하고 성과와 한계를 정리한 시점이다. 이후 실험을 다시 한다면 새 평가 기준과 제출 예산을 정한 별도 작업으로 진행하는 편이 맞다.
